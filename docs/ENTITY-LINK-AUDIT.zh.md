# 实体连接离线审核

2026-10-14。审核固定的六源 `outputs/`：225 个实体组、448 对跨源链接，以及 132 条因名称、主体或多标识冲突而拒连的高风险记录。审查范围共 779 条相关原始记录。仅使用原始数据、随附文档、现有配置和输出；没有模型 API 调用、外部补全或六源推理重跑。

结论：修复两处通用连接契约问题。固定范围的离线复核保留全部 448 对旧链接，新增 31 对待审核提案；没有替换正式结果或填写人工判断。**目前仍为人工审核 0/50，precision 未知。**

## 原始证据检查

779 条记录逐一回查原生 reader 的记录 ID、原始内容和定位，全部一致。每个已输出 ABN/ACN 都绑定到现有配置的主字段，复核原 AST 的输出、原单元格的号码及类型，并另做独立 checksum 计算。

448 对旧链接的两端均通过这些检查，没有发现相互冲突的 canonical ABN/ACN/NZBN。437 对使用 ABN，11 对使用 ACN。该结果证明原值和类型一致，**不证明 448 对都是同一主体，更不是 measured precision**。

原文档的角色边界仍然重要：ATO 的说明支持 corporate tax entity 与 ABN 的上下文，但不直接证明注册法律名称；ACT 描述合同相对方，不独立证明号码所有权；QBCC 描述持牌人，其类别不能证明同一行 ABN 的归属。已连接的 85 条不同 QBCC 记录原文均标为 Company，这只支持主体类别相容，不能替代归属核验。SOR 的完整类型标签保留 ABN/ACN 区分，不补造法律名称。

逐对检查、779 条记录的字段及定位绑定、原文档哈希和全部拒连案例见 [审计证据](../evidence/entity-link-audit.json)。这些记录仅供审核，不进入模型提示或人工金标。

## H1：名称角色被混成一个集合

原 `_record_features` 将 `entity.legal_name` 和 `entity.trading_name` 合并，`_pair_reason` 再对任意名称做词交集判断。这违背本体的两条定义：legal_name 是注册名称、不是商号；trading_name 可以有多个。

该问题有两个方向：

- 同一有效标识下，公司注册名称与品牌名不同，或者同一主体有多个不同商号，会被误当成名称冲突。
- 两侧存在冲突的法定名称时，共同商号又可能掩盖冲突。该风险已用虚构案例复现，不能据此声称旧 448 对中已经发生此类错误合并。

修复保留法定名称的独立角色，只让可比较的法定名称参与现有名称冲突检查。商号既不制造法定名称冲突，也不能掩盖它；它仍不能单独提供连接依据。原有标识、主体、同锚点和阈值检查保持有效。

实现只依赖 canonical 字段角色，未加入来源名、原始列名、公司名、品牌名或已知号码规则。测试使用虚构来源、无语义的原始字段名、不同名称，并覆盖 ABN 与 ACN。

## H2：歧义拒绝后仍残留通过分数

多锚点歧义处理会将候选诊断改为 `accepted=false`，但未同步清除原 `link_confidence=0.99`。旧诊断中有 123 对受影响；它们没有成为正式链接，因此不是 123 对错误合并。

修复后，歧义拒绝同时将该诊断的固定策略分数设为 0，与其他拒绝分支一致。接受阈值仍为 0.99，没有调低阈值或改变为概率模型。0.99 本身不是已测量的正确概率。

每条高风险记录另保存原始名称／类型上下文及同类型号码对应的跨源对端。不能因目标是提高覆盖，就将后两类自动合并；也不能把保守策略的覆盖限制都算成数据缺失。

其余未链接记录中，7,722 条没有当前可用标识，14,424 条没有发现跨源共同标识。这些只保留原统计，本轮没有对它们逐条审核，也不将它们统一视为 bug 或用来估算召回率。

先补 8 项通用测试，旧实现有 4 个测试方法失败（包括 7 个失败子用例）；随后才修复。名称角色、标识／主体冲突、名称无锚点、关联方号码不能当本主体锚点、多锚点拒绝分数等边界均保留。相关测试 **15/15** 通过，历史回放验证 **1/1** 通过，完整离线测试 **465/465** 通过（18.532 秒）；Ruff 指定检查和 diff 检查通过。

历史回放不再用固定链接数量阻止有依据的修复，而是保留原配置、观察及摘要的哈希检查，逐对要求旧链接不丢失、原锚点不变，并要求每个新增对均来自旧名称误拒且满足角色与标识条件。它不以“更多链接”作为正确性证明。

本轮运行时代码仅修改 `identity.py`。策略标识更新为 `common-anchor-0.4-name-roles`，用于区分行为及其实体键；旧文件仍保留原策略身份。运行时由 `318ca052…` 更新为 `4392bdf9b7bbfdd0f70566a03c78abdf2494c8ac9e3146bc1ffcc05d769b0540`。271 项既有数据、配置、结果、文档及审核包文件 SHA256 全部未变；阈值保持 0.99。

本轮止于离线审核和通用 bug 修复，没有生成新的正式 links/profiles、重采样 50 对审核包、填写人工标签或执行下一项优化。
