## What changed in the harness

- Discovery now distinguishes a mapping's primary field from its dependencies, so using a field in a condition does not hide its independent meaning. Original documented code meanings may support equivalent ontology values.
- The planner receives read-only repair progress: actual AST and target changes, evidence-declaration changes, repeated structured diagnostics, and new versus cached lookups. Editing descriptions or omit reasons does not count as changing execution. This adds no semantic approval or candidate-selection rule.
- Linking keeps explicit-person/unknown-subject pairs for review when an identifier's ownership is unresolved. A missing counterpart type no longer removes this particular subject-risk check.

Configs were generated by the runtime's model calls. No source-specific branch, hand-written mapping, native-row edit, ontology change or evaluation-label injection was added. The final runtime passed **394 offline tests**, static checks and independent code review. These verify behavior and recovery, not model quality.

## Final development holdout

**Cooperatives registered in ACT**, published by Access Canberra under CC BY 4.0, was selected before inspecting its native data. The runtime was frozen at 06:08:30 UTC; the full original 17-row CSV and field metadata were downloaded afterward. Dataset-level catalogue metadata had been encountered previously; no retained native development/model-test history was found. This is a development holdout, not a claim about model pretraining.

The request supplied original metadata, unchanged native data, the existing ontology and no required fields. Separate limited source-agreement labels were frozen before model calls: 17 registered names and 17 registration-status opportunities. They never entered inference. [Input and provenance](data/unseen-source/README.md).

The harness found all 17 rows, but produced **no validated config and no formal output**. The original metadata had empty field descriptions. The model left the name unmapped before name review because its legal/trading role was unclear. The host rejected the proposed status mapping because the available evidence did not match its recognised entity-status semantics. The agent then stopped. Evaluation retains the denominator and reports **N/A**, not zero-error success. The original metadata contained an official Program Website link, but that metadata reached the inspection stage and was not carried into the later planning/mapping context. The repository already has a separate evidence-acquisition workflow; this run did not invoke it. The next general harness repair is to connect that existing acquisition and citation path, preserving useful source links across stages. Adding a status alias or hand-writing this source’s schema would not address that limitation.

An earlier runtime succeeded on a different NoWaste holdout, but failed to retain Business Names in its six-source run. That entire attempt is retained in the archive. Its success does not validate the final runtime and was not substituted for the failed Cooperatives result.

  --labels evidence/unseen-source-labels.json --evidence-root data/unseen-source/evidence
